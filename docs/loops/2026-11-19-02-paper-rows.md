## The three questions as answered

**What should change.** The note in the coffin — BLK `553,365 241×197` — is
three rows of horizontal text on a sheet tilted about −32° (counter-clockwise).
The app drew the translation as one enormous stack: three labels on the same
frame, 119px, upright, covering the panel and the artwork below it. It must draw
three lines, parallel, at the sheet's lean, each about the source glyph size,
and none on another.

**How to verify.** `npm run regression -- paper-rows` replays the page through
the real ONNX detector, the LLM reader and the translator, and checks the labels
the pipeline actually draws. `paperRowsSelfTest` runs the same geometry without
the network. The artifact is `out/regression/paper-rows.png`.

**Done when.** In the note's region: exactly three labels; each at −31.7° ±7°;
each within ±40% of a 24px glyph; no pair covering more than 40% of one label.
The negative side: the other groups' labels, the erase and the reader's text
must not change.

## What the cause was

The det head fits one leaned box to the note's ink: 265×31 at −31.7°, whose page
rectangle is 241×165. Three reader entries named that one box (`box: 1`) and
said `direction: "v"` (the reader takes the tilted rows for columns). The
fallback in `applyInclination` split the box's page rectangle — `165 / 3 = 55px`
rows — and put their centres on the page axis. That is not a split of the run:
most of that 165px is the rotation, the rows are 30px deep, and the run steps
along the text's perpendicular. The offscreen cell pass then took the whole slot
width for the glyph, and the typesetter measured 267px on it. Three frames came
out identical and 119px after the 0.6 fit, so all three labels stacked.

## What changed

| area | before | after | why |
|---|---|---|---|
| several entries on one leaned horizontal box | band split of the box's page rectangle (`acrossSize / entries`), centres on the page axis, no angle | the block rotated by the box's angle: 226px long, 90px deep; rows laid across that depth, one band each | the box is one row; the block holds the run |
| one row's depth | 55px (165/3) | 30px (90/3), drawn at 28px | 55px is the rotation, not a glyph |
| the label's direction | `"v"` from the reader: one glyph per row, text down the page | `"h"`: the rows read left to right, then rotate with the frame | the box is wider than it is tall; the reader's direction contradicted its own boxes |
| the drawn frame | three identical 229×165 frames | three parallel 217–226 × 28 bars, 30px apart across the text | parallel, adjacent, no overlap |
| the label's glyph | 267px measured, 119px drawn | 28px measured, 28px drawn (fit 0.97) | the glyph is the row, not the slot |
| the erase | the same frame three times | each row's own bar (plus the block crop the harness erases) | one frame did not cover three rows |
| the runner's label-overlap check | page-bbox intersection | the labels' own axes when they share an angle (rows along the frame's local x, columns along its local y) | three parallel tilted rows have 80%-overlapping page boxes while not touching; the old check would call the fix a stack, and a column measured with the row axes reads as one |
| `BlockReading.boxes` | plain rectangles | keeps the leaned box's angle, direction and line extents | the split needs the angle the box was fitted to |

Deliberately unchanged: the detector, the reader prompt, the single-entry path
(`tight = H·cos − W·sin`), the upright multi-entry band split, the erase gate,
and the group's own box. The reader still answers `v` for these rows; the fix
does not need it to be right, it uses the box the reader itself named.
